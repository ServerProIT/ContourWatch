# Следующие этапы и критерии выпуска

0.1.0 — первая сквозная реализация для стенда. Не объявлять безошибочность, промышленную стабильность или поддержку всех ОС по результатам коротких тестов.

1. На VM проверить установку, удаление, обновление с сохранением UUID/очереди, автозапуск после перезагрузки, службу/трей под обычным пользователем. Матрица Windows Server 2012 → 2022, Windows 10/11 и согласованные Linux.
2. Зафиксировать smartmontools и LibreHardwareMonitor + драйвер; испытать HDD, SATA SSD, NVMe, SAS, RAID и USB. Подготовить лицензированную offline-поставку. Без неё статусы недоступности корректны, но аппаратный мониторинг неполон.
3. Реализовать безопасное обновление через публичные GitHub Releases: manifest с min/max OS, arch, version, dataSchema, SHA256 и независимой подписью; публичный ключ в защищённой поставке, приватный ключ в отдельном хранилище издателя; проверка на старте и раз в 24 ч с jitter; учёт rate limits. Отдельный updater, служба stop/install/start, health check, rollback, запрет повторения неудачного выпуска, окно UTC и центральный запрет. Проверить подмену подписи, несовместимую ОС, сбой питания, неудачный запуск и откат. Общий GitHub token не внедрять.
4. Добавить персональные учётные записи, аудит действий, настройки отдельных групп/устройств и обнаружение клонированных идентичностей. Сейчас ключи общие для роли; интервалы и правила общие для парка.
5. Разделить raw SMART и частые снимки, архивировать диагностику; провести 72-часовой тест с 300 реальными агентами и историей репрезентативного объёма. Проверить размер WAL, очистку, резервное восстановление и время отклика панели под долговременной нагрузкой.
6. Redfish/iDRAC/iLO и vendor RAID — отдельные расширения. Обеспечить защищённые учётные данные и режим только чтения.
