# Linux-агент

Планируемые цели: Ubuntu 22.04/24.04, Debian 12/13, Rocky Linux 9, x86_64. Python 3.9+; systemd. ARM64 логически возможен для Python, но не проверен. x86 не заявляется. Сам сервер может размещаться на другом современном Linux.

```sh
# Ubuntu / Debian: пакеты можно заранее доставить с локального зеркала
sudo apt install python3 smartmontools lm-sensors
# Rocky Linux 9
sudo dnf install python3 smartmontools lm_sensors
sudo sh agent/linux/install.sh
```

Установщик не скачивает файлы из интернета. Он устанавливает файлы в `/opt/contourwatch`, создаёт `/var/lib/contourwatch`, регистрирует службу и оставляет её остановленной для настройки. Секреты доступны root; публичный статус не содержит токенов и читается треем. Родительский каталог 0711 позволяет проход к public, но не перечисление содержимого; очередь 0700, config.json 0600.

Создайте в панели одноразовый токен, сохраните в файл `/root/enrollment.txt` с правами 0600:

```sh
sudo python3 /opt/contourwatch/agent.py --configure \
  --server=https://monitor.company.local \
  --token-file=/root/enrollment.txt --name=LINUX-01 --group=Серверная
sudo systemctl start contourwatch
sudo systemctl status contourwatch
sudo journalctl -u contourwatch -n 100
```

После регистрации удалите исходный файл токена. Общий токен удаляется из конфигурации самим агентом после сохранения индивидуальных учётных данных. Для нового сервера: остановите службу, выполните configure с `--reregister` и новым токеном, запустите службу. Для смены имени/группы уже зарегистрированного устройства используйте панель. Не переносите `/var/lib/contourwatch` в шаблоны клонируемых машин.

Проверка без установки службы:

```sh
python3 agent/linux/agent.py --root=/tmp/contour-probe --once
```

Служба работает от root для SMART-доступа к блочным устройствам и некоторым контроллерам. У неё нет входящего порта, команд удалённого исполнения или управления вентиляторами. Для последующего ограничения привилегий нужен отдельный узкий привилегированный SMART-помощник; здесь он ещё не реализован. ReadWritePaths и ProtectSystem ограничивают запись, но не заменяют разделение привилегий. Драйверы датчиков и права устройств настраивает администратор; sensors-detect агент не запускает.

Графический трей независим от службы. Он необязателен на сервере без рабочего стола:

```sh
# В Debian/Ubuntu предварительно установите python3-venv из зеркала ОС.
sudo python3 -m venv /opt/contourwatch/tray-env
sudo /opt/contourwatch/tray-env/bin/pip install 'PySide6>=6.6,<7'
sudo install -m 644 agent/linux/contourwatch-tray.desktop /etc/xdg/autostart/
```

Для автономной установки подготовьте wheelhouse на машине с тем же Python/ABI и используйте `pip install --no-index --find-links=/media/wheelhouse PySide6`. PySide6 6.6+ может требовать Python новее 3.9 в зависимости от выпуска: для Rocky 9 используйте отдельный Python 3.11+ для трея, не меняя Python службы. Конкретная версия PySide6 и её системные зависимости должны быть зафиксированы после теста целевого рабочего стола. В GNOME может понадобиться расширение поддержки AppIndicator; при отсутствии трея выводится сообщение, служба продолжает работу. Автозапуск начнётся в следующем графическом сеансе. Трей запускайте от обычного пользователя.

Linux-агент исключает сетевые и служебные файловые системы из сбора томов. Зависание statvfs или утилиты ограничено родительским процессом 25 секундами. RAID и USB требуют совместимого драйвера/типа smartctl; универсальная поддержка не заявляется. Общий предел SMART-сборщика 25 секунд означает, что на медленных или многодисковых системах потребуется развитие частичного/параллельного обхода.

Для удаления службы: `sudo sh agent/linux/uninstall.sh`. Программа и данные сохраняются для восстановления; удаляются администратором отдельно. Проверка установки, перезагрузки и трея на настоящем Linux ещё не проведена.
