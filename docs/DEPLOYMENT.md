# Развёртывание и сопровождение

## Центральный сервер

Основная инструкция для выбранной пользователем схемы: **[Ubuntu-ВМ в Proxmox + отдельный Nginx Proxy Manager](UBUNTU-NPM.md)**.

В штатной работе интернет не нужен. Заранее загрузите образ Node и исходники. Встроенный SQLite API в Node 24.11.1 помечен экспериментальным, поэтому runtime зафиксирован и требует повторных тестов при обновлении. Один процесс сервера, локальный SQLite WAL, SSD и регулярная резервная копия. Не располагайте SQLite на SMB/NFS.

В deploy/.env задаются PUBLIC_URL, приватный APP_BIND_IP и TRUSTED_PROXY_IPS отдельного NPM. Compose больше не запускает Caddy и не открывает 443. TLS завершается на существующем NPM; его сертификат должен быть доверенным браузерами и агентами. Ключи ролей генерируются в постоянном /data и не попадают в .env/журналы. Не передавайте ключ администратора агентам.

Пользователи/агенты подключаются по HTTPS/443 к NPM. Он направляет HTTP на приватный IP Ubuntu-ВМ:8080; этот порт разрешается только NPM средствами Proxmox/network firewall. Одного UFW для Docker-порта недостаточно. Агенту нужны DNS, корректное время и доверенный корневой сертификат УЦ. Входящих портов у агента нет. PUBLIC_URL включает Secure cookie и фиксирует допустимый browser Origin; X-Forwarded-For учитывается только от явно доверенного TCP-источника. При локальном HTTP-тестировании без PUBLIC_URL Secure cookie по умолчанию отключён.

Контейнер непривилегированный, корневая FS read-only, volume /data постоянный, журналы ограничены, включены init, restart unless-stopped, healthcheck /ready и корректная остановка. /health проверяет живость процесса, /ready дополнительно доступность БД. Проверки после реальной перезагрузки вашей ВМ остаются обязательными.

### Переход с конфигурации 0.1.0

Новая конфигурация имеет фиксированное имя проекта contourwatch и volume contourwatch-data. Старое имя volume могло зависеть от каталога (например deploy_contour-data). До запуска остановите старую установку её прежней конфигурацией, сделайте backup, найдите прежний volume и укажите его имя в DATA_VOLUME_NAME. Не запускайте одновременно две версии сервера с одной БД. Если старые ADMIN_KEY/VIEWER_KEY хранились только в .env, новые автоматически генерируемые ключи будут другими: получите их через docker compose exec и сохраните защищённо. Учётные данные агентов хранятся в БД и сохраняются вместе с ней. Старую .env с ключами не публиковать.

Windows доверяет хранилищу сертификатов компьютера; для службы корневой сертификат устанавливается в LocalMachine, не только CurrentUser. Linux использует системное хранилище CA или явно заданный caFile в защищённом config.json. Отключения проверки TLS нет.

## Windows

.NET Framework 4.8 должен быть установлен заранее официальным автономным пакетом Microsoft. Проверка Release >= 528040 встроена в установщик; перезагрузки и системные обновления выполняются средствами администрирования. EXE пока без цифровой подписи издателя: выпуск для массовой эксплуатации требует подписания и проверки доверия.

Соберите `powershell -ExecutionPolicy Bypass -File installer/build.ps1` из корня проекта. Выходной каталог `dist/windows-x64`. В графическом установщике можно проверить `/health`, сертификат и доступность API; недоступность сервера не запрещает завершить установку. Запуск службы Automatic, восстановление через SCM: 10/30/60 секунд. Трей — отдельный процесс при входе пользователя.

Тихое развёртывание GPO под администратором/SYSTEM:

```powershell
ContourSetup.exe --silent --server=https://monitor.company.local --token-file=C:\Secure\enrollment.txt --name=PC-01 --group=Office
```

Для массового пакета выдайте токен на ограниченное количество машин/время; доставляйте его отдельным файлом с ACL только SYSTEM/Administrators и удаляйте после установки. Секрет не передаётся параметром командной строки. Повторная регистрация: те же аргументы плюс `--reregister` и новый токен. Изменение сервера без нового токена отклоняется. При обновлении тем же установщиком сохраняются идентификатор, учётные данные и очередь; фактический upgrade/downgrade ещё требует испытания в VM. Закройте старые процессы трея перед обновлением файлов.

LocalSystem выбран для будущего доступа smartctl к физическим дискам и аппаратному драйверу. Это широкие права; модель разделения привилегий пока не реализована. Каталог ProgramData\ContourWatch: только SYSTEM/Administrators; подпапка public — чтение обычным пользователям, содержит только состояние и адрес панели. Конфигурация защищена одновременно ACL и DPAPI LocalMachine. Одна DPAPI LocalMachine без ACL не изолирует секреты от других пользователей машины.

`ContourSetup.exe --uninstall` останавливает/удаляет службу, автозапуск и запись приложения. Данные и сам установщик сохраняются намеренно; проверьте необходимость их хранения и удалите вручную. Нельзя включать ProgramData\ContourWatch в клонируемые образы. Защита от случайного слияния: случайный UUID, отдельный секрет, идемпотентная регистрация. Обнаружение уже клонированных установленных учётных данных автоматически пока не реализовано.

## Хранение, резервирование, восстановление

Подробная история: 30 дней; часовые RAM avg/max и CPU max: 365 дней, настраивается в панели. Агрегаты считаются при поступлении пакета; повтор пакета не увеличивает счётчик. Графики панели пока показывают последние 360 пакетов, агрегаты доступны через API. Отдельного UI выбора годового диапазона пока нет. Очистка выполняется каждый час. Текущая запись устройства сохраняется до административного удаления (удаление устройства пока не реализовано; есть отзыв доступа).

Оценка для 300 устройств при одном снимке в минуту: 432 000 пакетов/сутки. Для 8 КБ JSON — около 3.46 ГБ/сутки или 104 ГБ/30 дней без индексов. Для 20 КБ — 8.64 ГБ/сутки, 259 ГБ/30 дней. Исходный SMART в каждом снимке может сильно увеличить объём. Планируйте запас 1.5–2×, измеряйте на своих данных. Нужен следующий этап оптимизации: передавать аппаратные данные отдельно от частых метрик, сжимать/ограничивать повторение raw SMART, нагрузка на длительной истории. Короткий тест не доказывает работу 30-дневной базы указанного размера.

Online backup: `sudo sh deploy/backup.sh /защищённый/каталог`. Скрипт использует SQLite backup API и quick_check, сохраняет БД, оба ключа и .env с ограниченными правами. Самостоятельно выполнить только копию БД можно через `node server/backup.mjs --output /путь/к/новому/snapshot.sqlite`; назначение не должно существовать. Не копируйте только .db у работающей базы обычным cp. Альтернатива — остановить сервер и сохранить весь volume. Сертификат/настройки отдельного NPM резервируются на его сервере. Восстановление сначала репетируйте на отдельном volume; порядок описан в UBUNTU-NPM.md.

Локальная очередь агента: максимум 1500 снимков или 50 МиБ; при интервале 60 секунд — до 25 часов, в зависимости от размера. Самые старые удаляются с записью в журнал; это сознательный предел, бесконечная гарантия доставки не заявляется. Пакеты старше 7 суток агент отбрасывает. Журналы Windows 2×1 МиБ, Linux 3×1 МиБ. Журнал Linux systemd дополнительно регулируется настройками journald. Невалидный JSON в очереди удаляется с записью ошибки, а не блокирует следующие пакеты.
