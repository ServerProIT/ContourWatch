# Панель 0.3.0 и агенты 0.2.0

## Вход и пользователи

Вход только по персональному логину и паролю. Старые `admin.key`, `viewer.key`, `ADMIN_KEY*`, `VIEWER_KEY*` больше не дают доступа к веб-панели. Секрет устройства и токен регистрации агентов остаются: это отдельный протокол.

При обновлении сохраняется существующий персональный администратор и его пароль. Если администраторов нет, при запуске создаётся `admin` со случайным временным паролем в `/data/initial-admin.txt`, права 0600. На первом входе требуется смена пароля. Повторный запуск пароль не меняет. Второго администратора нельзя создать, существующего нельзя удалить, отключить или понизить. Если в старой базе несколько администраторов, запуск останавливается до ручного выбора основного; автоматического удаления пользователей нет.

Менеджеры управляют панелью и обычными пользователями, но не изменяют администратора. Читатель видит устройства, показатели и историю; собственный пароль и выбор колонок может менять. Отключение пользователя немедленно аннулирует его сеансы. Включение сохраняет пароль и настройки колонок.

Первый вход на новой установке:

```sh
cd /opt/contourwatch/deploy
sudo docker compose exec server cat /data/initial-admin.txt
```

Выводите пароль только в своём административном терминале. После его смены удалите файл с временным паролем из volume и защищённых копий по вашей политике хранения.

Локальное восстановление администратора, если пароль потерян (панель временно недоступна):

```sh
cd /opt/contourwatch/deploy
sudo docker compose stop server
sudo docker compose run --rm --no-deps server node server/admin.mjs reset-password /data
sudo docker compose run --rm --no-deps server sh -c 'cat /data/admin-reset-*.txt'
sudo docker compose up -d server
```

Команда сбрасывает пароль существующего администратора, завершает его прежние сеансы и требует сменить временный пароль. Она не создаёт дополнительного администратора. Файл сохраняется с уникальным именем и правами 0600, пароль в журнал не печатается.

## Устройства и интерфейс

Правая карточка появляется сразу с последними полученными показателями и временем измерения. Подробности, компактная история и события запрашиваются независимо; ошибка одного раздела не скрывает другие. При переходе к другому ПК старые запросы отменяются. Список устройств не передаёт полные аппаратные дампы и диагностику; они загружаются для выбранного ПК.

Диагностические события свёрнуты. Все измеряемые показатели имеют отдельные графики при наличии хотя бы двух числовых точек: RAM, тома, температура и загрузка CPU/GPU, вентиляторы, видеопамять, SMART и износ. Подсказка у указателя показывает время с миллисекундами и точное значение; также работают стрелки, Home/End и Escape. Пропуски и недоступные данные не превращаются в нули.

Каждый том выводится отдельно в одной колонке. Процент и шкала: до 50% зелёные, 50–84.999% жёлтые, от 85% красные. Группы создаются отдельно; устройство может входить в несколько групп. В фильтре доступны несколько групп, несколько состояний, совпадение любой/всех групп и дополнительная сортировка. Отозванные ПК изначально скрыты. Колонки сохраняются в аккаунте. Светлая/тёмная тема веб-панели сохраняется в браузере; тема агента — в настройках текущего пользователя ОС.

## Проблемы и почта

В конструкторе укажите тип показателя, конкретный ID датчика при необходимости, устройство/группы, условие, порог и порог восстановления, длительность нарушения и категорию. «Обычные» серые, «Не критичные» жёлтые, «Критичные» красные. Выключенное правило не создаёт проблемы. Изменение правила завершает его прежние активные события; следующая свежая выборка оценивается по новым параметрам. Предустановленные правила сохраняют прежние общие пороги до первого редактирования; после редактирования используют собственные параметры.

Почтовое правило требует **конкретные ПК и конкретные правила проблем**, затем почтовые каналы. Два правила одного типа можно направлять разным получателям. Учитываются задержка, восстановление, повторные попытки и журнал доставок. Обслуживание, отзыв и пауза подавляют отправку. После обновления старые широкие правила без точных селекторов отключены и помечены для проверки; выберите ПК/проблемы и сохраните их. Настройка SMTP описана в [WEB-0.2.0.md](WEB-0.2.0.md); тестовое письмо отправляется только по явному нажатию «Тест».

## Пауза агента

Панель сразу прекращает принимать новые метрики и отправлять оповещения для ПК. Агент 0.2.0 получает команду по аутентифицированной служебной связи примерно раз в 30 секунд, завершает уже запущенный ограниченный по времени сбор и подтверждает паузу. Новые сборы и доставка очереди не запускаются, история/регистрация сохраняются. Служебная связь и обновления продолжаются. После возобновления запускается новый сбор. Старая очередь хранится с обычным лимитом и сроком 7 дней; исторические пакеты не заменяют более новые показатели.

Агентам старше 0.2.0 нужна однократная ручная установка: они не умеют получать команду паузы и подписанные обновления. До подтверждения панель показывает ожидание агента. Это не удалённая остановка службы ОС.

## SMART и износ

Windows MSI включает неизменённый `smartctl` 7.5 x64, базу дисков, лицензии и соответствующие исходники. На Linux нужен системный пакет `smartmontools`; для ATA-процентов предпочтительна версия с JSON `endurance_used.current_percent`. Износ берётся из этого поля или NVMe `percentage_used`. Он может превышать 100% (предел протокола 255); это оценка производителя, а не прогноз даты отказа. HDD обычно не сообщают процент износа. RAID/USB-контроллер может скрывать SMART — тогда видна недоступность, а не «здоровый диск». Не производится запись SMART-тестов или изменение накопителей.

PawnIO нужен отдельно для части температур и вентиляторов Windows. Он не нужен для работы smartctl. Можно включить официальный подписанный установщик PawnIO в отдельный bootstrap-пакет с явным системным запросом установки; это требует проверки условий распространения, версии и совместимости. В этой поставке сторонний драйвер автоматически не устанавливается. Не подменяйте официальный установщик извлечённым драйвером и не отключайте Secure Boot/защиту Windows.

## MSI и обновления

Сборка Windows: `installer/build.ps1`, затем `installer/build-msi.ps1`. MSI содержит службу, датчики, smartctl, трей и настройщик. После установки откройте «Configure ContourWatch» и задайте HTTPS-адрес/токен. До настройки служба показывает ожидание конфигурации. Удаление MSI выполняется через установленные приложения Windows; конфигурация/история очереди сохраняются.

При переходе с прежнего EXE сначала запустите его `ContourSetup.exe --silent --uninstall`, сохранив `%ProgramData%\ContourWatch`, затем установите MSI. Последующие MSI используют штатное major upgrade. Прямое замещение старого EXE-сервиса средствами MSI не заявляется.

MSI не является гарантией от предупреждений Defender/SmartScreen или другого антивируса. Для репутации издателя нужна доверенная Authenticode-подпись и проверка реальной поставки. В этой сборке такого сертификата нет; RSA-подпись выпусков для автообновления не заменяет Authenticode. Исключения антивируса не создаются, защита не отключается.

Автообновления из GitHub Releases `ServerProIT/ContourWatch` по умолчанию выключены. В панели задаются stable/pilot и окно установки в часах UTC, включая переход через полночь. Агент проверяет выпуск примерно раз в час со случайной задержкой; перед установкой повторно проверяет политику. Сеть работает только исходящими запросами. Произвольные URL и команды установки с панели не принимаются.

Установка допускается после проверки закреплённым публичным RSA-ключом манифеста, срока, версии, фиксированного имени, размера и SHA-256. Неподписанный/изменённый/просроченный выпуск или понижение версии отклоняются. Windows сохраняет предыдущий кешированный MSI, Linux — предыдущие программные файлы; при неподтверждённом запуске выполняется откат. Linux применяет пакет отдельной transient systemd-службой, чтобы остановка агента не прервала обновление и не ослабляла ограничения основной службы. Данные устройства не входят в архив обновления.

`installer/package-release.ps1` (PowerShell 7.4+) подготавливает MSI, Linux-архив, `manifest.json`, `manifest.sig`, контрольные суммы в `dist/release`. Для подписи нужен закрытый ключ в DPAPI CurrentUser файле, путь задаётся `-KeyFile`. Закрытый ключ не хранится в Git и не передаётся агентам. Сохраните его резервную копию через согласованную процедуру безопасного хранения: DPAPI-файл привязан к профилю Windows, простого переноса на другой ПК недостаточно. Без подписывающего ключа следующий выпуск не будет принят установленными агентами; ротация ключа требует отдельного доверенного обновления.

Пока подписанные артефакты не опубликованы в GitHub Releases, автоматическая доставка нового агента из репозитория не начнётся. Для уже установленных агентов 0.1.x первым шагом остаётся ручная установка 0.2.0.

## Проверки и ограничения

API/права/миграции/почтовая маршрутизация проверяются Node-тестами; SMART, подписи и архивы — отдельными Windows/Python-тестами. CI устанавливает службу и MSI в одноразовой Windows VM, проверяет repair/upgrade/uninstall; Ubuntu проверяет Docker и восстановление резервной копии. Фактические результаты конкретной сборки фиксируются отдельно. Локальная разработка не подтверждает измерения на вашем физическом SSD/RAID, датчики платы, перезагрузку вашей VM или отсутствие предупреждений вашего антивируса.
