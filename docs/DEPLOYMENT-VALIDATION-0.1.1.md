# Проверка адаптации под Ubuntu и Nginx Proxy Manager — 0.1.1

Дата: 13 ноября 2026 года. Агентский код не менялся, его версия остаётся 0.1.0. Этот отчёт дополняет исходный VALIDATION.md.

## Изменения

- Основной Compose теперь запускает только панель на приватном IP:8080; Caddy удалён. HTTPS обслуживает существующий отдельный NPM.
- PUBLIC_URL задаёт точный допустимый HTTPS Origin и Secure cookie; forwarded host/proto не управляют авторизацией.
- TRUSTED_PROXY_IPS учитывает X-Forwarded-For только от явно разрешённого непосредственного TCP-источника. Цепочка читается справа налево, адрес браузера слева не считается достоверным.
- Отдельные случайные ключи admin/viewer сохраняются в /data. Есть явные ключи/файлы ключей с проверкой конфликтов и слабых значений. В журнал ключи не выводятся.
- Добавлены /ready с проверкой БД, read-only rootfs, ограничение журналов/процессов, init, корректная остановка и постоянный именованный volume.
- Online backup использует SQLite backup API, quick_check и атомарную публикацию без перезаписи существующего файла. Shell-сценарий сохраняет БД, ключи и конфигурацию с SHA256SUMS.
- Подготовлены up.sh, backup.sh, инструкция Proxmox/Ubuntu/NPM, описание миграции старого volume и ключей.
- Форма входа направляет за ключом к администратору, не показывает пользователю внутренние пути контейнера.

## Локальные проверки

`node --test tests/*.test.mjs`: **70/70**, включая прежние 45 и 25 новых проверок конфигурации, прокси и backup. Проверены реальный локальный reverse-proxy процесс с NPM-подобными заголовками, вход/сессия за ним, недопустимый Origin, подмена forwarded IP, разделение rate limit, сбой readiness, WAL backup, открытие восстановленной БД и запись в исходную после backup. HTTPS-сертификат настоящего NPM в этом локальном тесте не использовался.

Docker Compose CLI **v5.7.1**, официальный release asset, SHA256 проверен по metadata GitHub: `config --format json` прошёл; проверены один сервис, приватный bind, постоянный volume и read-only rootfs. Это проверка реальным Compose CLI, не имитация YAML-парсером. Docker Engine локально не установлен.

`sh -n` для обоих shell-сценариев и `node --check` для новых entrypoints прошли. После первого прогона исправлен порядок закрытия тестовой БД до очистки временного каталога на Windows; функциональные assertions backup и затем полный набор прошли.

## Автоматическая проверка на Ubuntu

Добавлен `.github/workflows/verify.yml`: Ubuntu 24.04 runner, Node 24.11.1, API/proxy/backup tests, Linux portable tests, сборка/запуск Docker Compose, проверка контейнера и данных после restart, online backup shell-сценарием и восстановление в отдельный временный volume с запуском от непривилегированного пользователя. В CI используются только отдельные disposable volumes и тестовые данные; secrets проекта/инфраструктуры не нужны. Результаты запуска смотреть в [GitHub Actions](https://github.com/ServerProIT/ContourWatch/actions).

На момент подготовки этого файла workflow ещё требуется выполнить после публикации. Само наличие workflow не означает успешный запуск.

## Что остаётся проверить на площадке

Реальную Ubuntu-ВМ в Proxmox, отдельный NPM, DNS/сертификат, точный source IP прокси, firewall (в том числе недоступность :8080 со стороннего узла), запуск после перезагрузки ВМ и приём показателей настоящих агентов. Тест restart контейнера не заменяет reboot ВМ.

Прежние ограничения аппаратных зависимостей, старых ОС, персональной авторизации и отсутствующего безопасного автообновлятора агентов сохраняются. Текущая панель предназначена для пилотного развёртывания, а не заявляется полностью аттестованной промышленной системой.
