# Агент и панель 0.1.2

## Обновить панель и агент

Сначала панель на Ubuntu VM, затем Windows-агент:

```sh
cd /opt/contourwatch
sudo sh deploy/backup.sh /mnt/secure-backups/contourwatch
sudo git pull --ff-only origin main
sudo sh deploy/up.sh
```

Укажите свой защищённый каталог backup. В браузере обновите страницу Ctrl+F5. NPM остаётся на отдельном сервере; существующие PUBLIC_URL, TRUSTED_PROXY_IPS, volume и ключи сохраняются. Не используйте down -v.

Скачайте новый [ContourSetup.exe](../downloads/windows-x64/README.md), проверьте SHA256 и запустите от администратора. Сохраните прежний адрес сервера. При обычном обновлении повторная регистрация не нужна. Если доступ устройству отозван, создайте новый токен и включите «Повторная регистрация». История прежней идентичности сохраняется отдельно.

Новый агент отправляет дополнительные типы CPU/GPU только после объявления поддержки сервером. На старом сервере остаются прежние метрики; чтобы видеть GPU и исправленный отзыв, панель тоже необходимо обновить. Первые расширенные данные появятся после согласования возможностей и следующего пакета (по умолчанию около минуты).

## Почему прежде были только ОЗУ и тома

В 0.1.1 аппаратная библиотека не была включена в установщик. Теперь LibreHardwareMonitor 0.9.6 входит в поставку; исходный архив проверяется SHA256. CPU и вентиляторы платы читаются отдельным процессом с ограничением времени. GPU внутри LHM отключён: native NVML crash не должен мешать сбору CPU.

Для температуры процессора и вентиляторов платы установите отдельно официальный **подписанный** драйвер [PawnIO](https://pawnio.eu/) через официальный сайт (кнопка в установщике), затем перезапустите службу:

```powershell
Restart-Service ContourWatch
```

Не выбирайте unsigned/unrestricted edition и не отключайте Secure Boot, HVCI, антивирус или проверку сертификатов. Драйвер не устанавливается агентом автоматически. Чтение зависит от платы, BIOS, драйвера и поддержки библиотекой. Загрузка CPU может читаться без PawnIO; наличие модели процессора в WMI/реестре само по себе не даёт доступа к температуре.

NVIDIA: установленный драйвер должен предоставлять nvidia-smi.exe в System32 или Program Files/NVIDIA Corporation/NVSMI. Агент запрашивает температуру, загрузку, вентиляторы в процентах, занятую/общую видеопамять. Запросы только на чтение. Нулевые обороты/0% при остановленных вентиляторах допустимы; N/A отображается как недоступность. AMD GPU-адаптер пока отсутствует. SMART по-прежнему требует отдельно установленный smartctl.

Любой недоступный датчик имеет null и состояние/причину, а не выдуманный ноль. Native crash и timeout сборщика не завершают основную службу. На имеющемся тестовом ПК без PawnIO проверена загрузка CPU и явная недоступность температуры; native crash nvidia-smi отразился как ошибка сборщика. Это не проверка показаний физической RTX 5070 пользователя.

## Отзыв доступа

«Отозвать доступ» открывает подтверждение, затем обновляет карточку и список. Статус «Доступ отозван» имеет приоритет над «В сети» и обслуживанием. Сервер отклоняет последующие пакеты с HTTP 401; графики истории сохраняются. Сам установленный сервис не удаляется удалённо и может продолжать локальный сбор/повторы. Для нового подключения нужны новый регистрационный токен и повторная регистрация.

## Журналы и диагностический ZIP

Windows: C:\ProgramData\ContourWatch\agent.log — JSONL с UTC, версией, уровнем, компонентом, кодом события и ограниченными полями. Ротация: текущий файл и три архива около 1 МиБ каждый. Пишутся переходы состояния сборщиков и доставки, причины TLS/DNS/HTTP, задержка повторов и размер очереди. Не записываются HTTP bodies, токены, device secret и конфигурация. Последние 24 события передаются в карточку устройства; подробная ошибка датчика — в «Диагностика и исходные данные».

Из PowerShell администратора:

```powershell
& "C:\Program Files\ContourWatch\ContourAgent.exe" --diagnostics "$env:USERPROFILE\Desktop\Contour-diagnostics.zip"
```

ZIP создаётся только по новому пути и включает application logs, публичный status.json и manifest. config.json, очередь пакетов и credentials исключены по списку разрешённых файлов. Содержимое нужно просмотреть перед передачей: журналы всё равно могут содержать сведения об ошибках среды и адрес сервера. Архив не отправляется автоматически. Старые журналы до обновления могут иметь прежний текстовый формат.

Сервер: `cd /opt/contourwatch/deploy && sudo docker compose logs --tail=100 server`. Отклонённые HTTP-запросы имеют X-Request-Id и запись с тем же requestId, методом, шаблоном маршрута, статусом и длительностью. Headers, query strings, неизвестные URL, тела запросов и секреты не журналируются. Не открывайте полные логи Docker публично.

## Проверки

Локально: 74 Node/API-теста, 14 self-tests Windows-агента, C# проверки классификации CPU, NVIDIA CSV (несколько GPU, кавычки, N/A, нулевые вентиляторы, повреждённые данные), TLS-политики, JSONL/redaction/rotation, ZIP без приватных файлов. Сквозной тест Windows проверяет реальный RAM/volumes, offline queue, регистрацию, повторы, битый пакет и deduplication. Проверка точного entrypoint установщика успешно открыла /health на monitor.serv-pro.ru с TLS 1.2 и нормальной проверкой сертификата, без токена.

Браузерный тест на вымышленных данных: GPU-колонка/график, подтверждение отзыва, немедленный статус и отключение повторной кнопки; ошибок console нет. CI дополнительно проверяет чистую службу Windows, обновление с 0.1.1 при открытом трее, повторную регистрацию без завершения неизменённого трея, restart, uninstall; Ubuntu Docker — restart и backup/restore.

Не подтверждены: фактические температуры на конкретной Ryzen/RTX 5070 системе, все материнские платы, полная перезагрузка Windows и все старые Windows Server. Пилотная версия; безопасный автоматический обновлятор пока отсутствует.
