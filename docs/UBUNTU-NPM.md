# Ubuntu-ВМ в Proxmox + отдельный Nginx Proxy Manager

Целевая схема версии панели 0.1.1:

```text
Браузер / Windows-агент / Linux-агент
                 │ HTTPS :443
                 ▼
    существующий Nginx Proxy Manager
                 │ HTTP :8080, приватная сеть
                 ▼
      Ubuntu Server VM → Docker → Контур
                                └→ SQLite /data
```

TLS и сертификат обслуживает NPM на другой ВМ/сервере. Caddy больше не нужен. Панель слушает порт 8080 только на выбранном адресе Ubuntu-ВМ. Внутреннее соединение NPM→панель не зашифровано: используйте доверенный изолированный сегмент/VLAN; через недоверенную сеть нужен отдельный TLS/VPN между серверами.

## 1. Подготовить ВМ

Для пилота: Ubuntu Server 24.04 LTS x64 (22.04 также целевой вариант), 2 vCPU, 4 ГиБ RAM, VirtIO-сеть на нужном bridge Proxmox, стабильный IP/DHCP reservation. Параметры — начальная оценка, не результат длительного теста на 300 машинах. Дисковое место рассчитывайте по фактическому размеру снимков: подробная история может занять сотни ГБ. Проверьте реально доступный размер раздела, а не только виртуального диска. Docker по умолчанию хранит volume под /var/lib/docker. Политика истории описана в DEPLOYMENT.md.

Рекомендуется QEMU Guest Agent для корректного выключения и работы инфраструктуры резервирования. В настройках ВМ Proxmox включите QEMU Guest Agent после установки гостевого пакета. Снимок работающей ВМ не заменяет проверенную прикладную резервную копию SQLite.

Далее используются **примерные** адреса, замените их на свои:

| Параметр | Пример |
|---|---|
| Ubuntu-ВМ панели | 192.168.10.40 |
| Отдельный сервер NPM | 192.168.10.10 |
| Имя панели | monitor.example.com |

## 2. Docker и исходники

Установите Docker Engine и Compose plugin по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Docker Desktop в серверной ВМ не требуется. Команды проекта используют `sudo docker compose`; добавление пользователя в группу docker не обязательно.

```sh
sudo apt update
sudo apt install -y git ca-certificates qemu-guest-agent
sudo systemctl start qemu-guest-agent
sudo systemctl enable --now docker
sudo docker compose version

sudo git clone https://github.com/ServerProIT/ContourWatch.git /opt/contourwatch
cd /opt/contourwatch/deploy
sudo cp .env.example .env
sudo chmod 600 .env
sudo nano .env
```

Если пакет qemu-guest-agent не запускается, проверьте включение соответствующего канала в конфигурации ВМ. Это не зависимость самой панели. Не запускайте приведённые команды создания клона поверх существующего каталога с данными; для обновления есть отдельный раздел ниже.

Пример содержимого `.env` для указанных выше адресов:

```dotenv
PUBLIC_URL=https://monitor.example.com
APP_BIND_IP=192.168.10.40
APP_PORT=8080
TRUSTED_PROXY_IPS=192.168.10.10
DATA_VOLUME_NAME=contourwatch-data
```

`PUBLIC_URL` — именно будущий адрес браузеров и агентов, только HTTPS, без подпапки. `APP_BIND_IP` — адрес **панели**, не NPM. Значение 127.0.0.1 в шаблоне безопасно, но отдельная ВМ NPM через него не подключится. `TRUSTED_PROXY_IPS` — адрес TCP-источника NPM, видимый контейнером; при обычном подключении с другой ВМ это адрес NPM. Если есть SNAT/маршрутизатор, сначала определите фактический адрес. Не указывайте `*`, всю подсеть или 0.0.0.0. Без настройки forwarded-заголовки игнорируются, а ограничения частоты будут общими для клиентов прокси.

Никаких паролей в .env создавать не нужно: разные случайные ключи администратора и наблюдателя генерируются при первом запуске и сохраняются внутри постоянного volume. Не меняйте DATA_VOLUME_NAME после запуска: другое имя означает другое, первоначально пустое хранилище. Старый volume автоматически не удаляется.

## 3. Ограничить внутренний порт

На внешнем firewall/Proxmox firewall разрешите входящий TCP/8080 к IP панели **только с IP NPM**. Убедитесь, что для указанного интерфейса ВМ действительно применяются правила, сохранён административный SSH-доступ и есть доступ к консоли Proxmox. Не пробрасывайте 8080 из интернета. Для пользователей нужен HTTPS/443 на NPM, а не HTTP/8080 на панели.

**Одного UFW внутри Ubuntu недостаточно для опубликованного Docker-порта:** Docker может обойти его правила. Используйте корректно настроенный Proxmox/network firewall либо точечные правила DOCKER-USER в зависимости от backend Docker. Не отключайте управление iptables в Docker. [Ограничения Docker/UFW](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations), [правила Docker](https://docs.docker.com/engine/network/firewall-iptables/).

## 4. Запустить панель

```sh
cd /opt/contourwatch
sudo sh deploy/up.sh
```

Сценарий проверяет Compose, собирает контейнер и ждёт `/ready`. На первой установке нужны интернет/локальное зеркало для загрузки базового образа; штатная работа панели не зависит от доступа в интернет. Node/npm на самой Ubuntu устанавливать не требуется.

Проверка из Ubuntu-ВМ (подставьте её IP):

```sh
curl --fail http://192.168.10.40:8080/ready
cd /opt/contourwatch/deploy
sudo docker compose ps
sudo docker compose logs --tail=100 server
```

Ключи для входа (выводите только на своём административном терминале):

```sh
sudo docker compose exec server cat /data/admin.key
sudo docker compose exec server cat /data/viewer.key
```

Они не выводятся в журналы приложения. Ключи общие для роли; личные учётные записи пока не реализованы. Повторный запуск/пересборка контейнера с тем же volume сохраняет БД и ключи.

## 5. Создать Proxy Host в Nginx Proxy Manager

DNS-запись `monitor.example.com` должна указывать на NPM (для LAN можно использовать внутренний DNS). Создайте Proxy Host:

| Поле NPM | Значение |
|---|---|
| Domain Names | monitor.example.com |
| Scheme | http |
| Forward Hostname / IP | 192.168.10.40 |
| Forward Port | 8080 |
| Cache Assets | выключено |
| Websockets Support | не требуется текущей панели |
| SSL Certificate | доверенный сертификат для monitor.example.com |
| Force SSL | включено |

Вкладка Advanced:

```nginx
client_max_body_size 2m;
proxy_connect_timeout 5s;
proxy_read_timeout 30s;
proxy_send_timeout 30s;
```

Сам API ограничивает JSON 1 МиБ; запас 2 МиБ у NPM нужен для предсказуемой обработки лимита приложением. Стандартные Host/X-Forwarded-For NPM уже передаёт, не дублируйте proxy_set_header в Advanced. Контур сверяет browser Origin с PUBLIC_URL, а не с недоверенным X-Forwarded-Host.

Используйте сертификат публичного УЦ или внутреннего УЦ, доверенного всеми агентами. Для имён `.local` публичный Let's Encrypt не подходит. Проверку сертификата в агентах не отключать. NPM Access List с дополнительным Basic Auth на **весь** хост помешает регистрации/передаче агентов: текущий агент не поддерживает второй пароль прокси. Ограничивайте доступ сетевыми правилами/VPN и используйте встроенные учётные данные панели/агентов. Не добавляйте к агентскому API HTML-страницы входа или редирект на SSO.

После сохранения:

```sh
curl --fail https://monitor.example.com/ready
```

Откройте https://monitor.example.com, войдите ключом администратора, создайте токен подключения. Агентам задавайте этот же HTTPS-адрес, **не** IP:8080.

## 6. Проверить перезагрузку и сохранение

Docker Engine должен быть включён в автозагрузку; restart: unless-stopped возвращает ранее запущенный контейнер после старта Docker. Контейнер, который администратор явно остановил, может оставаться остановленным. Сначала зарегистрируйте тестовое устройство, затем перезагрузите ВМ и проверьте `/ready`, вход прежним ключом, сохранение устройства и поступление свежих данных. Такой тест на вашей ВМ ещё нужно выполнить.

## 7. Резервирование и обновление

```sh
cd /opt/contourwatch
sudo sh deploy/backup.sh /mnt/secure-backups/contourwatch
```

Это согласованная online-копия SQLite через backup API с quick_check, а также ключи и .env. Сервис не останавливается. Каждый успешный backup — отдельный каталог с SHA256SUMS. Каталоги `.incomplete-*` означают незавершённую операцию, не используйте их для восстановления. Не храните единственную копию на той же ВМ. Каталог содержит секреты — ограничьте доступ, обеспечьте шифрование/защиту хранилища. Скрипт не удаляет старые backup: задайте политику хранения на backup-сервере.

Обновление приложения, отдельно от будущего автообновлятора агентов:

```sh
cd /opt/contourwatch
sudo sh deploy/backup.sh /mnt/secure-backups/contourwatch
sudo git pull --ff-only origin main
sudo sh deploy/up.sh
```

Не используйте `docker compose down -v`: этот флаг удаляет volume с данными. Не удаляйте volume при обычном обновлении. После обновления проверьте health, вход и поступление данных. Перед откатом версии убедитесь в совместимости миграций; откат кода не равен откату БД.

Для восстановления: остановить контейнер, проверить SHA256SUMS выбранного backup, сохранить прежний volume, восстановить contour.db и оба key-файла в отдельный подготовленный volume с владельцем UID/GID 1000 и правами 0600 для файлов/0700 для каталога, указать его в DATA_VOLUME_NAME, запустить и проверить. Не оставляйте старые WAL/SHM рядом с восстановленной БД. Старую БД/volume не удаляйте до успешной проверки. Отдельного автоматического restore-скрипта пока нет; сначала отрепетируйте восстановление на тестовом volume.

## Если что-то не работает

- **502 на NPM:** доступ с сервера NPM к `http://IP_ВМ:8080/ready`, правильный bind IP, firewall, состояние контейнера.
- **403 при входе:** точное совпадение HTTPS-имени/порта с PUBLIC_URL. После изменения .env повторите up.sh.
- **Вход не сохраняется:** открывайте HTTPS через NPM, не внутренний HTTP. Cookie Secure намеренно не работает через HTTP.
- **429 для разных операторов:** проверьте фактический source IP NPM и TRUSTED_PROXY_IPS. Без доверенного прокси лимит общий.
- **Пустая база после пересборки:** сравните DATA_VOLUME_NAME/`docker volume ls`; не регистрируйте парк заново до проверки старого volume.
- **Недостаточно места:** проверьте `df -h`, размеры Docker volume/backup, политику истории и повторяемость raw SMART. Не удаляйте живую БД или WAL вручную.

Версия 0.1.1 остаётся пилотной. Настройка тестировалась локальными автоматическими сценариями; реальная связка Proxmox→Ubuntu→NPM, сертификат, firewall и перезагрузка вашей ВМ требуют проверки на месте. Изменения этого этапа не включают безопасный автообновлятор агентов или квалификацию датчиков.
