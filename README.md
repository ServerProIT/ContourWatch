# Контур / ContourWatch

Собственная система мониторинга оборудования Windows и Linux для локальной сети. Панель **0.4.4**, Windows-агент **0.2.3**, Linux-агент **0.2.3** — для стенда и пилотной проверки. Полная готовность к промышленной эксплуатации не подтверждена.

Полноэкранная карточка устройства, компактная сводка и выровненные фильтры. «Настроить вид» выбирает целые блоки: перенос переставляет соседей в сетке, угол и поля Ш/В меняют размеры. Настройки сохраняются отдельно для аккаунта; Escape завершает редактирование. Анимации учитывают системное уменьшение движения.

Персональная Главная 0.4.0: устройства, выбранные показатели, история, сравнение и диаграммы состояний/проблем. Конструктор доступен каждому пользователю. Менеджерам и администратору доступно подтверждаемое удаление отозванных ПК. [Подробности](docs/PERSONAL-HOME.md).

Таблицы 0.4.1: ширина столбцов и высота строк доступны сразу, перенос работает с целыми строками и столбцами. Конструктор переставляет целые блоки в сетке. [Управление таблицами и блоками](docs/STRUCTURE-EDITOR.md).

Агент 0.2.1: просмотр локальных логов, снимок причин недоступности датчиков, сохранение TXT/ZIP и единая тема всех окон. [Инструкция](docs/AGENT-DIAGNOSTICS.md).

## Ubuntu в Proxmox + Nginx Proxy Manager

Основной способ развёртывания: отдельная Ubuntu-ВМ с Docker, HTTPS на существующем NPM на другом сервере. [Пошаговая инструкция и поля Proxy Host](docs/UBUNTU-NPM.md).

```sh
sudo git clone https://github.com/ServerProIT/ContourWatch.git /opt/contourwatch
cd /opt/contourwatch/deploy
sudo cp .env.example .env
sudo nano .env
# PUBLIC_URL=https://ваше-имя, APP_BIND_IP=приватный-IP-ВМ,
# TRUSTED_PROXY_IPS=IP-отдельного-NPM
cd ..
sudo sh deploy/up.sh
```

Требуется Docker Engine с Compose plugin. NPM направляет HTTP на IP панели:8080; пользователи и агенты обращаются к внешнему HTTPS-имени. Начальные логин/пароль новой установки: `cd deploy && sudo docker compose exec server cat /data/initial-admin.txt`. Существующий персональный администратор сохраняется. Порт 8080 разрешайте только серверу NPM через Proxmox/network firewall. Caddy и сертификаты внутри контейнера панели не нужны.

База и персональные аккаунты сохраняются в постоянном volume `contourwatch-data`. Online backup: `sudo sh deploy/backup.sh /путь/к/защищённым/копиям`. Не удаляйте volume при обновлении; не используйте `down -v` на своей ВМ.

Проверено на Ubuntu 24.04 в [GitHub Actions](https://github.com/ServerProIT/ContourWatch/actions/runs/43384195374): 70 серверных тестов, 15 Linux logic tests, сборка/запуск контейнера, сохранение после restart и backup/restore. [Отчёт 0.1.1](docs/DEPLOYMENT-VALIDATION-0.1.1.md). Реальные NPM, Proxmox firewall и reboot вашей ВМ ещё нужно проверить.

[Изменения 0.3.0: карточка, проблемы, SMART, пауза, MSI и подписанные обновления](docs/RELEASE-0.3.0.md).

## Что уже работает

- API регистрации и приёма показателей; ограниченные регистрационные токены, отдельные отзываемые учётные данные устройств.
- SQLite с WAL, миграциями, защитой от повторных пакетов, текущими значениями, историей и часовыми агрегатами.
- Панель на русском: светлая и тёмная темы, поиск, группы, сортировка, карточка устройства, графики, события, обслуживание, подтверждение, персональные аккаунты администратора, менеджера и читателя.
- Windows x64: служба C#/.NET Framework 4.8, самостоятельный трей, MSI и EXE-настройщик, тихая установка, DPAPI, ограниченная очередь, повторная доставка и независимые сборщики с тайм-аутами.
- Linux: Python 3.9+, служба systemd, самостоятельный трей на PySide6, очередь, регистрация, SMART и lm-sensors через отдельные процессы.
- Собственные SVG-иконки панели и агента, ICO для Windows.

## Старт сервера без Docker

Установите **Node.js 24.22.3 LTS**. Зависимости npm не нужны.

```sh
node server/main.mjs
```

Откройте `http://127.0.0.1:8080`. На новой установке логин и временный пароль находятся в `data/initial-admin.txt`; при первом входе требуется смена пароля. Старые ключи веб-доступа удалены. Существующий персональный администратор сохраняется. [Новые функции, миграция, MSI и обновления](docs/RELEASE-0.3.0.md).

Сервер по умолчанию доступен **только через loopback**. Для работы агентов необходим HTTPS через обратный прокси и доверенный сертификат. Пример: [развёртывание](docs/DEPLOYMENT.md).

```sh
node server/main.mjs --demo
```

Демо использует отдельную `demo.db`, показывает явное предупреждение и моделирует устройства. Для производственной базы запускайте без `--demo`. Не подключайте настоящие устройства к демонстрационному серверу.

## Агенты

Windows 0.2.0: сборка `installer/build.ps1`, затем `installer/build-msi.ps1`; результат `dist/windows-x64/ContourWatch-0.2.0-windows-x64.msi`. После установки откройте Configure ContourWatch и задайте HTTPS-адрес/токен. Для перехода с прежнего EXE сначала удалите старую службу его настройщиком, сохранив ProgramData. [Инструкция 0.3.0](docs/RELEASE-0.3.0.md). Подписанные выпуски доставляются через GitHub Releases после их публикации. В downloads сохранён исторический EXE 0.1.2. Нужен .NET Framework 4.8; сторонний драйвер PawnIO не вложен.

Linux: [установка и ограничения](docs/LINUX.md). Цели пилотной поддержки: Ubuntu 22.04/24.04, Debian 12/13, Rocky Linux 9; реальные проверки на этих дистрибутивах ещё не выполнены.

## Проверки

```sh
node --test tests/*.test.mjs
python3 tests/linux_test.py
python3 tests/linux_update_test.py
node tests/load.mjs
```

Windows, после сборки:

```powershell
.\dist\windows-x64\ContourAgent.exe --self-test
node tests/windows-e2e.mjs
```

Сквозной тест использует отдельный временный каталог и loopback API, не устанавливает службу. Исключение HTTP допускается агентом только при явном локальном тестовом режиме и только для loopback. Обычный установщик принимает HTTPS.

## Границы готовности

**Подписанные обновления агентов реализованы и по умолчанию выключены.** Укажите канал и окно UTC в разделе «Обновления». Проверяются закреплённая RSA-подпись, версия, срок, SHA-256 и размер; отдельный установщик подтверждает запуск и выполняет откат. После неудачного запуска этот выпуск блокируется. Агентам 0.1.x нужна однократная ручная установка 0.2.0. Автодоставка начнётся после публикации подписанных артефактов в GitHub Releases.

**Датчики Windows:** LibreHardwareMonitor 0.9.6 включён в установщик и работает в отдельном процессе, CPU/GPU разделены. Температура CPU и вентиляторы платы требуют отдельно установленный официальный подписанный PawnIO. NVIDIA собирается независимым read-only вызовом nvidia-smi из установленного драйвера. Отдельный AMD GPU-адаптер пока отсутствует. smartctl 7.5 для SMART/износа включён в Windows-поставку вместе с лицензией и соответствующими исходниками. [Датчики, журналы и обновление 0.1.2](docs/AGENT-0.1.2.md).

Установка/удаление, SCM restart и обновление с работающим треем проверяются в CI на Windows Server 2025. Не проверены: полная перезагрузка Windows, интерактивное меню трея во всех пользовательских сеансах, Server 2012/2012 R2/2016/2019/2022, полный аппаратный прогон Linux-агента (systemd-обновление/откат отдельно проверяются на синтетической службе в CI), реальное Linux-оборудование, RAID/USB, чтение датчиков на конкретной плате Ryzen/RTX 5070. Исходный [отчёт 0.1.0](docs/VALIDATION.md) дополняется [проверкой развёртывания 0.1.1](docs/DEPLOYMENT-VALIDATION-0.1.1.md).

## Устройство проекта

| Каталог | Содержание |
|---|---|
| `server` | API, события, SQLite, миграции |
| `web` | Автономный интерфейс, темы, оригинальные SVG |
| `agent/windows` | Служба, изолированные сборщики, трей |

Публичность репозитория сама по себе не является лицензией. Лицензия проекта владельцем пока не выбрана. Сторонние компоненты: [THIRD_PARTY.md](docs/THIRD_PARTY.md).
